    Wi-Fi QR code

    Generate a password with the "Wi-Fi password" preset above, then turn it into a QR code here — scanning it joins the network directly, with nothing to type or mistype. Standard camera and QR apps recognize this format.

    Temporary session history

    History is off by default. If you turn it on, previously generated values will be kept in memory only, only for this browser tab, only until you close, refresh, or navigate away from this page. Nothing is written to disk. Turn it on only if you understand and accept this trade-off.

    Export batch results

    Exported files contain sensitive data in plain form. Anyone with access to the downloaded file can read every password it contains. Store and delete it carefully.

    Decrypt a protected value

    Paste one or more protected values from a QR code or export from this tool (one per line) — either passphrase-protected (SPGENC1:) or security-key-protected (SPGYK1:) — and recover the original password or passphrase. Nothing here is sent anywhere — decryption happens locally, the same as generation.

    Security-key decryption only works on the hosted (HTTPS) version of this page, and needs the same physical key used to protect the value.

    Key vault

    Save passwords here using each result's "Save to vault" button, then download the vault as one encrypted file to keep or carry to another device. The vault lives only in this tab's memory and in whatever file you explicitly download — nothing here is ever written to this browser's storage automatically, and like the rest of this page, it's cleared if you switch away from or close this tab. Download it before you navigate away.

    Whoever has the vault file and a way to unlock it (its passphrase, or the security key that protected it) can read everything in it. Pick a strong, memorable passphrase (a generated passphrase from this tool works well) and keep it separate from the file itself. If you protect a vault with only one method and lose it — forget the passphrase, or lose the security key — there is no way to recover the vault. Protecting it with both gives you a second way in if you lose one of them.

    Security guidance

    1. Use a different, unique password for every account so a breach in one place can't unlock the rest.
    2. Prefer a reputable password manager to store and autofill unique passwords, rather than memorising or reusing them.
    3. Enable multi-factor authentication wherever it is offered, in addition to a strong password.
    4. Longer, randomly generated passwords are generally stronger than shorter ones, even with fewer character types.
    5. Passphrases are only as strong as their word selection: words must be chosen independently and randomly, not picked by hand.
    6. Don't reuse a password you generate here for another account, even if it looks strong.
    7. Avoid sending passwords through insecure or unencrypted messaging channels; use a password manager's sharing feature or another secure channel instead.
    8. Some websites restrict allowed characters or length; those restrictions can reduce the effective strength of an otherwise strong password.
    9. Short PINs are generally much weaker than long random passwords and should be reserved for contexts (like device unlock) with other protections such as attempt limits.
    10. Avoid pasting important passwords into unfamiliar "password strength checker" websites — you can't verify what they do with the data.
    11. A QR code of a password is the password: anyone who can scan, screenshot, or photograph it can read it. Use the "QR code" option only on a private screen to move a password to your own other device, and close it once you're done.
    12. A Wi-Fi QR code lets any device that scans it join the network immediately, with no password prompt at all — treat it exactly like posting the password itself. Show it only to people and devices you want on your network, and take it down (or stop displaying it) afterward.
    13. The "Spell it out" phonetic view is meant for reading aloud on a live call, not for writing down, pasting, or texting — sending that list electronically carries exactly the same risk as sending the password itself.
    14. For extra protection when transferring a password — over a photo, a synced clipboard, or an exported file — encrypt it with a passphrase first. Communicate that passphrase a different way than the code or file itself (say it aloud, don't attach it to the same message), and never write the two down together.
    15. The key vault's master passphrase (or security key) is the only thing standing between the downloaded file and every password in it, indefinitely. A weak passphrase can eventually be guessed offline — use a long, random one (a generated passphrase from this tool is a good choice) and don't reuse it as an account password anywhere. A security-key-protected vault has no such guessing risk, but can only ever be opened with that exact physical key — losing it means losing the vault.
    16. A physical security key (e.g. a YubiKey) can replace a typed passphrase for QR/export protection: touch the key instead of remembering a secret. This only works on the hosted (HTTPS) version of this page, and decrypting requires the exact same physical key — if you lose it, a value protected this way cannot be recovered.
    Technical & privacy information
    • Random values are produced using window.crypto.getRandomValues(), the browser's cryptographically secure pseudorandom number generator (CSPRNG). Math.random() is never used.
    • Random integer selection uses rejection sampling to avoid modulo bias.
    • All generation happens entirely in your local browser tab.
    • This page makes no network requests. There is nothing to intercept in transit because nothing is sent anywhere.
    • Generated password and passphrase values are not intentionally written to cookies, localStorage, sessionStorage, the URL, or the console.
    • Entropy figures shown are mathematical estimates based on the configured character pool or word list size; they are not guarantees of real-world crackability.
    • User-selected restrictions (exclusions, required-group placement, duplicate prevention, pattern avoidance, first/last character rules) can reduce the true search space below the raw calculation.
    • JavaScript running in a browser cannot guarantee secure erasure of values from device memory. This page clears references it controls when a value is regenerated, cleared, or the page is hidden/unloaded, but this is a best effort, not a certified secure-wipe. Random-password generation builds each candidate in a numeric buffer it owns exclusively and actively overwrites once a value has been extracted, rather than only relying on eventual garbage collection — the resulting string itself, like all JavaScript strings, is still immutable and cannot be wiped. This buffer-level clearing does not extend to passphrase words: a chosen word remains referenced by this page's embedded word list for as long as the page is open regardless of what happens to any other reference to it, so there is nothing meaningful to overwrite there.
    • Browser extensions, a compromised device, screen capture, clipboard managers/history tools, and malware can still expose passwords displayed or copied on any web page, including this one.
    • The "QR code" view is generated by this page's own JavaScript and rendered as an inline SVG graphic. The password is never encoded into a data: URL, an <img> source, or any network request; the graphic is removed from the page when the dialog is closed.
    • Passphrase protection (for a QR code, an export, or the key vault) uses only the browser's built-in Web Crypto API: PBKDF2 (SHA-256, 600,000 iterations) derives an AES-256 key from your passphrase, and AES-GCM encrypts the value with a random salt and IV. This is not custom cryptographic code — it calls the browser's own, independently-audited implementation. The passphrase is used only in memory for that one operation and is never stored, logged, or transmitted.
    • The key vault's entries live only in this tab's memory and in whatever encrypted file you explicitly download — there is no automatic save to localStorage, IndexedDB, or any server, and the in-memory list is cleared on the same hide/close/unload triggers as every other sensitive value on this page.
    • A vault file protected by both a passphrase and a security key uses envelope encryption: a random key encrypts the vault data once, and that random key is then separately encrypted ("wrapped") once per protection method you chose. Either method decrypts its own wrapped copy of the same random key, which is what actually unlocks the data — so either one opens the file independently, without the other. Choosing only one method still works exactly as before; there's nothing to wrap twice unless you select both.
    • Security-key protection uses the browser's WebAuthn API and its "prf" extension: touching a registered physical key with a given random salt deterministically returns a secret, used directly as an AES-GCM key. The secret never leaves the hardware and is never visible to this page's JavaScript, only the result of that one derivation. Browsers refuse WebAuthn entirely on pages opened as a local file (a SecurityError, confirmed in testing) — this feature only works when the page is served over HTTPS or from localhost, and needs an authenticator and browser that both support the "prf" extension, which is detected and reported explicitly rather than assumed.
    • The optional "Speak" button under "Spell it out" uses the browser's built-in speechSynthesis API, which runs locally through the operating system's own text-to-speech engine on every browser tested; this page makes no network request to produce speech. Voice availability and quality vary by device and operating system, and a device with no voices installed will fall back to the on-screen text after a few seconds.
    Local self-tests

They exercise this page's code only and are not a cryptographic certification, nor proof that the underlying randomness is unpredictable. Passing statistical or structural checks does not, by itself, prove cryptographic security.
